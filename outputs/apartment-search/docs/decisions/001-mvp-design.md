# ADR 001 — 웹 MVP의 데이터 접근과 실행 환경

상태: 현재 구현을 기준으로 정리한 결정 기록 (2026-10-26).

## 목적

아파트 거래 검색 흐름을 먼저 구현하고, 이후 데이터 규모를 늘리며 검색 성능을 비교할 기준을 마련한다.

## 결정과 비용

| 결정 | 이유 | 비용 및 재검토 조건 |
| --- | --- | --- |
| Spring MVC + Thymeleaf | 단일 서버에서 검색 화면과 서버 로직을 함께 실행 | 화면 상호작용이 복잡해지면 프런트 구조 재검토 |
| JDBC | 검색 SQL·인덱스·실행 계획을 직접 확인 | 매핑과 동적 조건을 직접 관리해야 함 |
| OFFSET + COUNT | 페이지 번호와 전체 건수를 제공하는 초기 기준선 | 깊은 페이지·COUNT 비용을 측정하고 키셋 방식 비교 |
| H2 기본 실행 | 외부 DB 없이 기능 체험·테스트 | PostgreSQL 호환성과 성능을 보장하지 않음 |
| Flyway | 스키마 변경을 버전으로 관리 | 변경은 새 마이그레이션으로 추가 |
| localStorage 관심 저장 | 계정 없이 관심 목록 체험 | 기기 동기화 불가, 안정적인 단지 ID 필요 |
| 프로세스 내 요청 제한 | 단일 서버의 과도한 조회 억제 | 다중 서버·프록시 환경에서 정책 재설계 필요 |

## 다음 실험

PostgreSQL에 동일한 조건의 테스트 데이터를 적재하고 데이터 건수, 인덱스, 실행 계획, 동시 사용자, p95, 오류율을 함께 기록한다. 인덱스·키셋·캐시는 각각 비교할 가설이며 현재 성능 향상 수치는 없다.
