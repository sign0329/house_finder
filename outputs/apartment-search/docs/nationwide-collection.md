# 전국 최근 3개월 수집 준비

대상 계약월은 202607~202609. AWS는 중지 상태로 유지하고 로컬 Docker PostgreSQL만 사용한다. 전국 수집 완료 상태가 아니다.

## 지역 목록

`config/molit-regions.tsv`는 2026-10-30 [행정표준코드관리시스템](https://www.code.go.kr/stdcode/regCodeL.do)의 법정동 코드 전체자료에서 생성했다. 다운로드 양식 `/etc/codeFullDown.do`에 `codeseId=법정동코드`를 제출한 ZIP의 SHA-256:

`44a3fe4cacf88ce98e35fb883807d2725b589f427ff4d73ee40b914d1286bacd`

CP949 TSV에서 `폐지여부=존재` 행만 사용하고, 읍면동·리 코드의 앞 5자리를 중복 제거했다. 해당 5자리+00000 행에서 시군구 명칭을 얻는다. 하위 구가 있는 시의 상위 시 코드를 별도로 중복 호출하지 않는다. 세종은 36110 단위다.

총 256개 지역 중 229개는 현재 앱의 시도 명칭에 대응한다. 27개는 원본이 `전남광주통합특별시`여서 처음 보류했으나, 후속 API 검증으로 202607~202609 신코드 지원을 확인해 ready로 전환했다. 앱에 새 시도 선택을 추가하고 과거 광주/전남 선택은 별도로 유지한다. [코드 검증 기록](region-code-verification.md)을 참고한다. `ready`도 명칭 매핑 가능이라는 의미이며 과거 계약월의 완전한 커버리지를 보증하지 않는다. 현재 코드만으로 과거 행정구역 변경을 소급 해결하지 않는다.

## 실행

Python 3 표준 라이브러리와 Docker Compose를 사용한다. 프로젝트 폴더에서:

```sh
# API 호출 없는 계획 확인
python3 scripts/collect-nationwide.py
# 한 번에 최대 10개 지역·월 구간만 순차 실행
python3 scripts/collect-nationwide.py --execute --limit 10
```

기본 환경 파일은 `.env.docker`, 상태 파일은 `data/collection-2026q3/progress.json`이다. 다른 체크아웃에서 실행할 때는 `--env-file`과 `--state-dir`에 기존 파일/디렉터리의 절대 경로를 명시한다. 재개 시 반드시 같은 환경 파일·DB·상태 디렉터리를 사용한다. 기본 기간은 명시적으로 2026년 7~9월이며 자동으로 이동하지 않는다.

- 지역·월 하나씩 기존 Java importer로 실행한다. 전체 페이지 검증과 저장은 기존 Java 로직을 재사용한다.
- 성공 구간은 건수가 0이어도 기록하고 다음 실행에서 건너뛴다. 실패·중단 구간과 미실행 구간만 재시도한다.
- 실패하면 그 실행을 멈춘다. 로그 원문/URL/인증키를 상태 파일에 기록하지 않는다.
- 체크포인트는 임시 파일 쓰기 후 원자적 교체한다. 같은 상태 디렉터리는 파일 잠금으로 중복 실행을 막는다.
- 기본 구간 간 대기는 2초다. limit는 API 요청 수가 아니며 페이지 및 기존 HTTP 재시도에 따라 호출 수가 늘어난다. 일일 한도는 별도로 확인해야 한다.
- 15분 타임아웃 시 중단한다. 재개 전에 `docker compose ps -a`로 남은 importer를 확인·중지한다. 서로 다른 상태 디렉터리로 동시 수집하지 않는다.
- DB 복원·교체 후에는 과거 성공 체크포인트가 유효하지 않을 수 있으므로 새 상태 디렉터리를 사용한다. 이미 성공한 기간의 정정·해제 거래 재동기화도 별도 상태 디렉터리로 명시적으로 실행한다.
- 키는 Compose가 환경 파일에서 importer에 전달한다. 상태·덤프·환경 파일은 Git에 올리지 않는다.

## 실제 검증 (2026-10-30)

추가 자동 검증 5개: 월 경계/잘못된 기간, 성공 건너뛰기 및 실패·중단 재개, 정상 종료와 해당 구간 성공 로그의 일치, 중복 지역 거부, 상태 파일 저장. 기본 Java Maven verify도 통과했다. TDD red 관찰을 주장하지 않는다.

실제 종로구 202607/202608/202609 3구간: 각각 38/23/34건 성공 기록. 기존 9월 32건은 최신 34건으로 스냅샷 갱신됐다. 로컬 전체는 31,891건에서 **31,954건**이 됐다. 27개 지역은 이후 코드 검증만 진행했으며, 나머지 전국 구간의 거래 적재는 아직 진행하지 않았다. AWS 데이터는 변경하지 않았다.

지역 목록 변경으로 기존 체크포인트의 지문이 달라진다. 후속 수집은 `--state-dir data/collection-2026q3-v2`로 실행한다. 기존 기록을 삭제하거나 지문을 임의로 수정하지 않는다. 새 상태에서는 과거 성공 구간도 다시 조회하지만 기존 스냅샷 저장 로직으로 중복 적재를 방지한다.
