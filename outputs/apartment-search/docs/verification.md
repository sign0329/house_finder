## 과거 기록 — 2026-10-13

당시 Java 22.0.2에서 Java 21 타깃 빌드와 웹 테스트 8개가 통과했습니다. 브라우저에서 한강 검색, 관심 저장·유지, 상세 이동과 차트 및 반응형 레이아웃을 확인했습니다. 현재 버전의 전체 브라우저 회귀 테스트 결과로 해석하지 않습니다.

초기 구현에서는 최초 Red 실행을 관측하지 못했으므로 전체 구현을 Red–Green TDD로 주장하지 않습니다.

## PostgreSQL 검증 — 2026-10-26

- Docker Desktop 4.38 / Engine 27.5.1, Java 21.0.13, PostgreSQL 17.11에서 `./mvnw -B -ntp -Ppostgres-it verify` 성공.
- 기존 30개 + Testcontainers PostgreSQL 통합 7개 = 총 37개 통과(실패·오류·스킵 0).
- Flyway V1~V3, XML 저장·검색·상세, 정밀도, 중복·취소·정정·빈 월 처리, 실제 제약조건 오류의 롤백, 동시 수집 직렬화, 가상 데이터 혼합 거부 확인.
- 첫 실행은 Docker Desktop 소켓 마운트 경로 문제로 실패했다. 컨테이너 소켓 오버라이드를 적용한 후 통과했으며, 이 실패를 비즈니스 로직 TDD의 Red로 주장하지 않는다.
- 전용 Compose DB를 127.0.0.1:5433에 실행하고 실제 국토부 종로구 202609 거래 32건을 저장했다(해제 0건).
- PostgreSQL에 연결된 패키징 JAR을 8081에서 실행해 health UP, 검색, 상세, 두 번째 페이지, 출처 표시 확인. 기존 H2 서버와 데이터는 보존.
- 키·DB 비밀번호·수집 DB는 커밋에서 제외. 전체 앱 Compose 빌드, 운영 성능 및 백업 복구는 미검증.
- 실행 방법은 [PostgreSQL 안내](postgresql.md). 이전 섹션은 각 단계 당시의 검증 범위다.

## 지역·기간 수집 확장 검증 (2026-10-27)

- `-Ppostgres-it verify`: 기본 38개 + PostgreSQL 9개 = 총 47개 통과. 실제 공공 API 호출 없이 합성 XML/모의 Transport 및 임시 DB 사용.
- 다른 지역의 같은 월 데이터가 지워지는 회귀 테스트의 실패(1건 기대/0건 실제)를 먼저 관측하고 source_region 범위를 적용했다.
- 여러 지역·연도 경계를 포함한 월 범위, 기존 단일 월 옵션, 잘못된 입력 거부를 검증했다. 계획 미구현 상태에서 정상 입력 테스트 2개 오류를 확인한 뒤 구현했다.
- 2개 지역 × 2개월 중 1구간 실패 시 나머지 3구간 저장, 결과 순서, 재실행 ID 유지, 실패 구간 기존 데이터 유지, 지역·날짜 검색을 검증했다.
- 수집한 제주가 검색 선택지에 없는 테스트 실패를 관측한 뒤 DB의 실제 시도 목록을 반영했다.
- PostgreSQL에서 지역 스냅샷 분리와 V3 기존 행 → V4 업그레이드의 ID/source_key 보존을 검증했다.
- Compose 설정 검사로 지역 목록·기간 인자 전달과 웹 앱에 키가 전달되지 않음을 확인했다.
- 추가 지역 실제 응답, 공공 API 호출 한도, 대규모 성능은 미검증이다. 기존 실행 중인 앱·DB·실제 데이터는 수정하지 않았다.
