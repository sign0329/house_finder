# AI 활용과 검증 원칙

AI 코딩 도구를 활용해 웹 기능, 환경 설정, 테스트와 문서를 작성했다. 생성된 코드 자체를 검증 근거로 사용하지 않고 실행 결과와 요구사항을 기준으로 확인한다.

## 현재 수행한 것

- 요구사항·작업 규칙을 저장소 문서로 유지
- Maven verify를 통한 반복 가능한 테스트
- 보안 수정 전 신규 테스트 3개 실패 관측, 수정 후 전체 13개 통과
- 패키징된 의존성 좌표를 OSV로 조회하는 스크립트

초기 구현의 최초 실패 실행은 관측하지 못했다. 전체 개발을 TDD로 했다고 주장하지 않는다. 완성된 자율 검증 하네스도 아직 구축하지 않았으며, 현재는 문서·스크립트·테스트를 검증 기반으로 사용한다.

## 변경 시 작업 순서

1. 요구사항과 기존 구현을 확인하고 변경 범위를 정한다.
2. 도메인 규칙 변경은 의미 있는 실패 테스트를 먼저 실행한다.
3. 구현 후 테스트와 해당 실행 경로를 확인한다.
4. 결과, 실행 환경, 미검증 사항을 문서에 반영한다.

공공 API를 부하 대상으로 사용하지 않는다. 비밀 값과 개인 환경 캐시는 저장소에서 제외한다.
