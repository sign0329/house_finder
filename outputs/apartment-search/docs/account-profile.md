# 마이페이지와 프로필 사진

## 사용자 흐름

일반 사용자 로그인 성공 시 항상 홈(`/`)으로 이동함. 관리자는 기존대로 `/admin`으로 이동함. 상단 마이페이지 메뉴에서 프로필과 본인의 관심 아파트 목록을 확인함. 거래가 삭제된 관심 항목은 그대로 표시하고 현재 조회 가능한 거래가 없음을 안내함. 관심 해제는 기존 관심 목록 관리 화면에서 제공함.

## 사진 저장

- 로그인한 사용자만 `/account/photo`에서 본인의 사진을 등록·조회할 수 있음. 사용자 ID를 요청으로 받지 않고 인증된 계정명을 사용함.
- 업로드·삭제는 POST와 CSRF 토큰을 요구함.
- 파일 내용 기준 PNG/JPEG만 지원함. 확장자와 Content-Type을 신뢰하지 않음.
- 2MB 이하, 가로·세로 4096px 이하, 800만 화소 이하를 허용함. 디코딩 전 크기를 검사함.
- 비율을 유지해 긴 변 최대 256px로 축소하고 PNG로 다시 인코딩함. 원본 파일명과 메타데이터는 저장하지 않음.
- V10 마이그레이션으로 `user_account.profile_photo` BYTEA 컬럼을 추가함. 계정당 한 장을 DB에 저장하므로 앱 컨테이너 교체 시에도 유지됨.
- 사진 응답은 `Cache-Control: no-store`로 반환함. 기본 사진은 파일 없이 HTML로 표시함.
- 기존 계정의 사진은 NULL이며 별도 데이터 보정이 필요하지 않음.

## 검증

구현 전 로그인 이동과 마이페이지·사진 관련 테스트 5개 실패를 확인함. 이후 이미지 정규화·계정 분리·잘못된 파일 및 용량 제한·CSRF·삭제·관심 목록 소유권을 검증함. PostgreSQL에서는 사진 저장 후 서비스 객체를 다시 만들어 읽고 삭제하는 검증을 추가함.

배포 시 V10 적용 전 운영 DB를 백업함. 저장 사진이 많아지면 DB 용량을 관찰하고 필요 시 객체 저장소로 분리함. 이번 구현에는 외부 저장소 비용이나 신규 클라우드 리소스가 발생하지 않음.
