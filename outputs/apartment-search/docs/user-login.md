# 사용자 계정과 로그인

사용자 페이지는 `/signup`(회원가입), `/login`(로그인), `/account`(내 계정), `POST /logout`(로그아웃)이다. 공용 메뉴에서 접근한다. 실거래가 검색은 로그인 없이 사용할 수 있다. 관심 아파트 목록·저장·해제는 사용자 로그인이 필요하다.

## 계정 저장

V7 `user_account`에 아이디, 닉네임, BCrypt 비밀번호 해시(비용 12), 가입 시각을 저장한다. 아이디는 영문 소문자·숫자·밑줄 4~30자이며 DB UNIQUE로 동시 중복 가입을 차단한다. 닉네임은 2~30자, 비밀번호는 12자 이상·UTF-8 72바이트 이하이고 확인 입력이 일치해야 한다. 실패 화면에 비밀번호를 다시 채우지 않는다. 닉네임은 Thymeleaf 텍스트 출력으로 이스케이프한다.

PostgreSQL 데이터 볼륨을 사용하면 계정도 영속화된다. 기본 local 프로필은 빈 메모리 H2이므로 재시작 시 계정이 사라진다. 미리보기에서 생성한 계정이 Docker/AWS DB로 자동 복사되지 않는다. 마이그레이션에는 기본 사용자나 예시 계정을 넣지 않는다.

## 인증 분리

사용자 로그인은 DB 계정 인증 관리자만, 관리자 로그인은 환경 설정 계정 인증 관리자만 사용한다. 동일한 아이디가 있어도 비밀번호·권한을 서로 대체할 수 없다. 가입 시 역할을 입력받지 않으며 사용자에게 ROLE_USER만 부여한다. `/account`는 USER, `/admin`과 관리 API는 ADMIN을 요구한다.

로그인 성공 시 세션 ID를 변경하고 30분 유휴 만료를 적용한다. 사용자와 관리자 인증은 같은 브라우저 세션을 사용하므로 다른 역할로 로그인하면 현재 로그인 신원이 바뀐다. 로그아웃은 해당 세션 전체를 폐기한다. 동시에 다른 역할로 사용할 경우 별도 브라우저 프로필을 사용한다.

회원가입·로그인·로그아웃은 CSRF 검증을 요구한다. 사용자 및 관리자 로그인과 가입 요청은 기존 인증 요청 제한(IP당 분당 10회, 프로세스 전체 분당 1,000회)을 공유한다. 실제 연결 IP 기준의 메모리 고정 구간 방식이며 다중 서버 공유 제한은 아니다. 운영 Compose는 HTTPS Secure 쿠키, 로컬은 HTTP 쿠키를 사용한다. 쿠키는 HttpOnly·SameSite=Strict다.

## 범위와 한계

계정 가입·로그인·로그아웃·내 정보 조회까지 제공한다. 이메일 인증, 비밀번호 재설정, 소셜 로그인, 탈퇴/프로필 수정, 관심 목록의 계정별 동기화는 아직 제공하지 않는다. 관심 아파트는 브라우저 localStorage에서 아이디별 키로 분리한다. 다른 기기와 동기화되지 않으며 브라우저 저장소 자체는 보안 저장소가 아니다.

## 검증

새 사용자 인증 테스트 5개를 구현 전 실행해 404/로그인 리다이렉트 실패를 확인했다. 가입 해시 저장·중복, 입력 검증·비밀번호 비노출, 로그인 실패/성공·로그아웃, 동일 아이디의 관리자/사용자 인증 분리, 공개 검색·CSRF 경계를 검증한다. PostgreSQL 통합 테스트는 동시 가입 두 건 중 한 건만 성공하고, 새 서비스 인스턴스에서 저장된 해시/USER 권한을 조회하는 것을 확인한다.

최종 `clean verify -Ppostgres-it` 결과: 기본 71개 + PostgreSQL 15개, 총 86개 통과. V7까지 마이그레이션 검증 완료. 18084 로컬 서버 기동 완료. 브라우저 검증은 자동 승인 검토의 사용량 제한으로 실행되지 않아 미완료다. 실제 수집·AWS 배포는 수행하지 않았다.

## 관심 아파트 로그인 제한

비로그인 검색·상세의 별은 로그인 링크다. /saved는 USER 세션을 요구하고, 저장·해제 직전에 /api/account/session에서 현재 계정을 확인한다. 만료되면 로그인으로 이동하고 계정이 바뀌었으면 새로고침하며 저장하지 않는다. 관리자 계정은 일반 사용자 관심 목록을 사용할 수 없다.

기존 공용 키 aptfolio.saved.molit.v1은 어느 계정의 목록인지 확인할 수 없어 자동 이관하지 않는다. 삭제하지 않고 보존하며 새 키 aptfolio.saved.molit.user.v1.<아이디>를 사용한다. 로그인 전 저장된 기존 목록은 새 계정 목록에 표시되지 않으므로 필요한 항목은 다시 등록한다.

검증: 신규 MVC 3개와 JS 2개. 구현 전 MVC 3개 실패 확인. 전체 Java 89개(기본 74 + PostgreSQL 15) 및 node scripts/test-bookmark-access.cjs 2개 통과. 브라우저 수동 검증·AWS 배포는 수행하지 않음.
