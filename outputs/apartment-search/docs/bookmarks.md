# 계정별 관심 아파트 저장

## 사용자 동작

로그인 후 검색·상세의 별을 누르면 DB에 저장한다. /saved에서 목록을 조회하고 해제할 수 있다. 같은 운영 서비스에 같은 계정으로 로그인하면 다른 기기에서도 동일 목록을 가져온다. 최대 200개이며 조회 실패를 빈 목록으로 표시하지 않는다. 로그인되지 않은 경우 로그인 화면으로 이동한다.

## 데이터와 권한

V8 user_bookmark는 user_account 외래 키와 사용자·아파트 키 유일 제약을 가진다. 아파트는 지역·시군구·이름·주소의 조합으로 구분하며 면적·층·거래월 차이는 하나의 관심 항목으로 묶는다. 서버에서 실제 거래를 조회해 식별 필드를 정하고 길이 접두사를 붙인 값의 SHA-256을 유일 키로 사용한다. 클라이언트가 소유자나 아파트 이름을 지정하지 않는다. 공식 단지 식별자가 아니므로 주소/단지명이 수정되면 별개 항목이 될 수 있다.

POST /api/account/bookmarks {"tradeId":1}, GET /api/account/bookmarks, DELETE /api/account/bookmarks/{id}. 모든 요청은 USER 권한을 요구하며 변경 요청에는 CSRF 검증을 적용한다. 소유자는 세션 Principal에서 결정하고 삭제 SQL에도 user_id 조건을 포함한다. 다른 사용자의 ID 삭제는 404다.

사용자 행의 FOR UPDATE 잠금으로 같은 사용자에 대한 저장·삭제를 직렬화한다. 중복 등록은 기존 ID를 반환하며 유일 제약도 유지한다. 200개 상한 확인과 삽입은 같은 트랜잭션이다. 목록은 최대 200개로 제한한다.

거래 ID 외래 키 대신 아파트 식별 정보를 저장한다. 수집 스냅샷 교체로 거래가 사라져도 관심 항목은 남는다. 조회 시 동일 아파트의 최신 계약일/ID 거래를 찾아 상세 링크로 반환하며 없으면 tradeId=null과 안내를 표시한다. 거래가 다시 들어오면 링크가 복구된다.

## 기존 브라우저 목록

localStorage 데이터는 삭제하지 않지만 DB로 자동 이관하지 않는다. 구형 공유 키/사용자별 키의 항목은 현재 서버의 계정 소유권과 실제 거래를 검증하지 않은 데이터이므로 화면에 합치지 않는다. 필요한 항목은 다시 등록해야 한다. 이후 신규 등록부터 DB에 저장된다.

## 운영과 검증

기존 마이그레이션은 수정하지 않았으며 V8만 추가했다. PostgreSQL 볼륨에 저장하면 재시작 후에도 유지된다. 기본 local 메모리 H2는 재시작 시 계정과 관심 항목이 모두 사라진다.

구현 전 관심 API 테스트에서 3개 404 실패 확인. 최종 Java 테스트 94개(기본 78 + PostgreSQL 16)와 node scripts/test-bookmark-access.cjs 2개 통과. 동일 단지 중복, 사용자별 조회·삭제, 거래 삭제 시 항목 보존, 인증·CSRF, PostgreSQL 동시 중복 등록/거래 재수집 후 링크 복구를 확인했다. JS 테스트는 만료 세션 차단과 서버 저장·다른 화면 조회·해제를 검증한다. 실제 브라우저/기기간 수동 테스트와 AWS 배포는 수행하지 않았다.
