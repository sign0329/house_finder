# 로컬 수집 데이터 서비스 반영 기록

- 작업일: 2026-11-10 (한국 시간)
- 원본: 로컬 수집 PostgreSQL (`house-finder-research-db-1`)
- 대상: 로컬 서비스 PostgreSQL (`house-finder-stack-db-1`, 웹 포트 8082)
- AWS: 변경 없음

## 결과

| 항목 | 거래 건수 |
| --- | ---: |
| 반영 전 서비스 DB | 129,728 |
| 복사 시점의 수집 DB | 695,740 |
| 중복 제외 신규 추가 | 566,049 |
| 반영 후 서비스 DB | 695,777 |

수치는 해당 반영 시점의 `trade` 행 수다. 전국 전체 수집 완료를 의미하지 않는다. 두 DB 사이 중복이 있으므로 건수를 합산하지 않는다.

## 처리 방법

1. 서비스 DB를 PostgreSQL custom-format으로 백업하고 `pg_restore --list`로 백업 목차를 읽을 수 있는지 확인했다. 복원 리허설까지 수행한 것은 아니다.
2. 수집 DB의 MOLIT 거래를 하나의 COPY 조회 스냅샷으로 읽었다. 회원·관심 목록은 복사하지 않았다.
3. 대상 DB의 수집 잠금을 획득하고 트랜잭션 내 임시 테이블에 적재했다.
4. `source_key` 충돌 시 기존 행을 유지하는 INSERT로 신규 거래만 추가했다. 원본 ID는 복사하지 않았으며 기존 서비스 거래 ID를 유지했다.
5. 원본 거래 키의 대상 존재 여부와 기존 ID·회원·관심 목록 보존을 트랜잭션 내 검증한 뒤 커밋했다.

## 확인 결과

- 복사한 원본의 모든 거래 키가 대상에 존재함을 확인했다.
- 기존 거래의 ID·키 조합과 기존 회원·관심 목록이 유지됨을 확인했다. 당시 회원·관심 목록은 각각 0건으로, 실사용 회원이 있는 경우의 검증 증거는 아니다.
- `/api/trades` 응답의 `total`이 695,777인 것을 확인했다.

## 한계와 후속 작업

원본보다 대상이 37건 많은 것은 대상에만 남아 있는 기존 거래를 삭제하지 않았기 때문이다. 이 기록만으로 해당 37건이 취소 거래라고 단정할 수 없다.

이번 작업은 신규 거래 추가이며, 원본에서 사라진 거래 삭제나 기존 행의 정정 반영을 포함하는 완전한 동기화가 아니다. 후속 작업에서는 수집 완료가 확인된 지역·월만 대상으로 정정·취소와 빈 결과를 검증한 뒤 동기화해야 한다.

DB 덤프, 실제 거래 파일과 환경변수는 로컬에만 보관하며 Git에 포함하지 않는다. 이번 커밋은 작업 기록이며 애플리케이션 코드나 데이터를 배포하지 않는다.
